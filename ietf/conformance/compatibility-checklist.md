# AEP Role and Profile Compatibility Checklist

This checklist is the executable contract baseline for AEP development kits. It assigns the behavior in every active draft to an implementation role and conformance profile. Cross-language adapter contracts and reports build on this inventory; they do not redefine it.

The normative drafts remain authoritative. Schemas validate bounded document shapes, vectors exercise deterministic behavior, examples explain complete exchanges, and the Node.js packages provide reference implementation evidence.

## Credential Profile Checklist

| Profile                 | Agent responsibilities                                                                                                        | Service responsibilities                                                                                               | Evidence                                              |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| OAuth Bearer Credential | Request only when advertised; validate and store the response; present `Bearer`; honor scopes and expiry; Revoke              | Advertise configuration; issue a bounded response; authenticate the presented token; revoke without disclosing secrets | OAuth draft and schema; OAuth vectors; transcript     |
| API-Key Credential      | Request only when advertised; validate and store the response; use the exact returned header; honor scopes and expiry; Revoke | Advertise allowed header configuration; issue a bounded key; authenticate only in the selected header; revoke          | API-key draft and schema; API-key vectors and example |
| Basic Credential        | Request only when advertised; validate and store the response; present Basic credentials; honor scopes and expiry; Revoke     | Advertise configuration; generate username/password values; authenticate Basic; revoke                                 | Basic draft and schema; Basic vectors and example     |

Grant and Revoke remain optional Core HTTP commands. An implementation claims a credential profile only for formats it implements; it does not claim every published credential profile merely because it supports Core HTTP.

## Freeze Rule

The active contract baseline is the seven drafts and six profiles listed above. A later draft revision, registered profile, wire-shape change, or public Node behavior that conflicts with a normative draft must update this checklist and the executable manifest together before another language copies it.
